# Brainstorming

## Purpose

Explore design ideas, constraints, and trade-offs before committing to an implementation approach.

## Process

### 1. Problem Definition
- Clarify what problem we are solving
- Identify constraints (performance, compatibility, timeline)
- Define success criteria

### 2. Exploration
- Generate multiple approaches (at least 3)
- Consider existing patterns in the codebase
- Research prior art and industry standards
- Identify risks and unknowns for each approach

### 3. Evaluation
- Compare approaches against constraints
- Assess complexity vs. value trade-offs
- Consider maintenance burden
- Evaluate testing difficulty

### 4. Decision
- Recommend an approach with justification
- Document rejected alternatives and why
- Identify open questions that need resolution
- Define next steps (move to /write-plan)

## Rules

- No code writing during brainstorming
- All ideas are valid during exploration
- Constraints must be explicit, not assumed
- Document the decision rationale for future reference
